1. 개요

safe-sensor-ecu는 레거시 C Basic Software(CAN FD/CAN XL, DMA, OS ISR)와 안전 핵심 신호 처리를 하드웨어 강제 파티션(C BSW 도메인 ↔ Unprivileged Safe-Rust SWC 도메인)으로 분리하는 개념을 실행 가능한 빌드(make all)로 보여주는 프로젝트입니다.

네 가지 기여를 하나의 빌드에서 시연합니다:

  1. Co-optimized Dual-Hall Gradiometer + Q2.13 TinyML 필터 — 3D Biot–Savart 시뮬레이터 위에서 6→32(ReLU)→3 FNN(288 MAC, 716 B ROM)을 학습/양자화하고 Formal IBP bounds를 계산합니다.
  2. 컴파일러 강제 Zero-unsafe Application SWC — ARXML-Lite 계약에서 #[repr(C)] ABI, C RTE 훅, RAII PimGuard 토큰, C-ABI shim을 자동 생성하여 swc_rust_app이 #![no_std] + #![forbid(unsafe_code)]로 빌드됩니다.
  3. 하드웨어 메모리 보호 스케치 — ARMv8-M PMSAv8 (STM32H563) 32-byte region + Infineon AURIX TC375 레지스터 매핑(헤더만)으로 파티션을 정의합니다.
  4. 1oo2 물리 플라우저빌리티 모니터 — dual-Hall 공간 그래디언트 bounds로 near-field 자기 스푸핑을 감지하여 Safe Neutral로 전이합니다.
중요: 본 프로젝트는 개념 데모입니다. 인증된 안전 ECU가 아니며, 실제 target 실리콘에서 검증되지 않았습니다. HIL은 host(Linux) 에뮬레이션이며, ML 메트릭은 합성 데이터 기반입니다.

3. 빠른 시작 (Quick Start)

git clone <repo>
cd safe-sensor-ecu
make all

make all은 다음을 순서대로 실행합니다:

  1. codegen — rte_gen/generate_rte.py + sim/train_and_quantize.py
  2. rust-host — cargo build --release
  3. arm-check — arm-none-eabi-gcc로 mpu_stm32h5_pmsav8.c 컴파일
  4. hil-test — HIL 빌드 + 11,500 사이클 실행

성공 시 build/hil_results.json에 "status": "PASS_ALL_11500_CYCLES"가 출력됩니다.

5. 코드 생성 (Codegen)

5.1 RTE 계약 생성 (rte_gen/generate_rte.py)

swc_contract.json(ARXML-Lite)에서 다음을 자동 생성합니다:

  • bsw_c/include/rte_generated.h — C RTE struct + _Static_assert (32 B PIM)
  • swc_rust_ffi/src/lib.rs — #[repr(C)] struct + PimGuard RAII 토큰 + FFI extern block
  • swc_rust_rte_entry/src/lib.rs — #[no_mangle] C-ABI shim

5.2 ML 학습/양자화 (sim/train_and_quantize.py)

3D Biot–Savart 시뮬레이터(24,000 샘플 학습 + 5,000 테스트)에서 6→32(ReLU)→3 FNN을 학습하고 Q2.13 고정소수점 가중치를 swc_rust_app/src/weights_generated.rs로 내보냅니다.

7. HIL 검증

HIL harness(hil_sim/hil_runner.c)는 host에서 다음을 검증합니다:

  • Suite 1: 10,000 Q2.13 FNN + PimGuard 사이클 (latency & determinism)
  • Suite 2: 500 near-field magnetic spoofing 공격 (ISO/IEC 27090-style)
  • Suite 3: 500 Rust panic!() fault injection (zero-reset partition recovery)
  • Suite 4: 500 hardware MPU illegal write injection

총 11,500 사이클, "status": "PASS_ALL_11500_CYCLES"가 출력되면 성공입니다.

HIL은 host 에뮬레이션입니다 (Linux mmap/mprotect + SIGSEGV + siglongjmp). ARMv8-M cycle-accurate 모델이 아니며, 일부 판정(예: missed deadline 카운터)은 tautological합니다. 자세한 한계는 § 8을 참고하세요.

8. 범위와 한계 (Honest Positioning)

이 저장소가 IS 하는 것

  • 합성 데이터 기반 Q2.13 FNN + 코드 생성 파이프라인
  • RAII PimGuard (nesting-safe, atomic re-entrancy guard 포함) 스케치
  • MPU 파티션 매니저 스케치 (host 컴파일만)
  • Host HIL fault-injection harness

이 저장소가 IS NOT 하는 것

  • 어떤 표준(ISO 26262, ISO/IEC 27090)에도 인증되지 않음
  • target 실리콘에서 검증되지 않음 (Rust는 host target 빌드, 베어메탈 이미지 미링크)
  • HIL은 cycle-accurate ARM 모델이 아님
  • AURIX TC375 매핑은 헤더만 존재 (코드/테스트 없음)
  • ML 메트릭은 합성 데이터 기반 (독립 테스트 세트 없음)

알려진 한계

  • Rust/C 권한 경계는 스케치 수준 (unprivileged Rust → privileged C 호출은 실제 target에서 HardFault)
  • HIL의 일부 판정은 tautological (EA nesting은 본 리비전에서 수정됨)
  • IBP 도메인(±130 mT)이 센서 선형 범위(±20–25 mT)를 초과
  • 가중치 클리핑은 경고 없이 수행됨

9. 문제 해결 (FAQ)

make all이 python3: command not found로 실패합니다.
Windows에서는 WSL2(Ubuntu)를 사용하세요. sudo apt-get install python3 python3-numpy gcc-arm-none-eabi.
arm-none-eabi-gcc가 없습니다.
ARM GNU Toolchain을 설치하고 PATH에 추가하세요 (Windows: C:\STM32_Tools\arm_toolchain\...\bin).
HIL이 SIGSEGV로 죽습니다.
WSL/Linux에서 실행해야 합니다. Windows 네이티브에서는 mmap/mprotect/sigaction이 동작하지 않습니다.
재현성이 걱정됩니다.
시드가 고정(RNG = np.random.default_rng(20261021))되어 있어 train_and_quantize.py 재실행 결과는 byte-identical입니다.
코드 생성물을 수동 편집해도 됩니까?
swc_rust_ffi/src/lib.rs, rte_generated.h, weights_generated.rs는 자동 생성 파일입니다. make codegen 실행 시 덮어쓰여집니다. 변경은 생성기(generate_rte.py, train_and_quantize.py)에서 하세요.
